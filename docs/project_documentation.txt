STATE SEGMENTATION & SUITABILITY SCORING — END-TO-END TECHNICAL AND BUSINESS DOCUMENTATION
==========================================================================================

Prepared for: MBA (Big Data Analytics) evaluation panel
Role: Lead Analytics Solution Architect & Project Lead
Build date / data refresh: 3 November 2026 · Scoring version: weights_v3 (v1 and v2 kept for audit)
· Live app: https://india-expansion-intel.vercel.app

Executive summary
-----------------

* Where should an established Indian business expand next?
    What we built: A state-screening decision app: 7 pilot states x 6 industries, scored against
      a 30-state national reference
    Headline result: A relative 0–100 suitability index with evidence, trade-offs, rank
      stability and data caveats for every recommendation

* Can we predict which states will grow?
    What we built: A leakage-controlled, one-year-ahead forecast of real manufacturing GSVA
      growth
    Headline result: Validated: 12% lower error than the best naive baseline; hold-out error 3.3
      pp vs 3.9 pp. Other five sectors are ranking-only because no defensible state-level target
      exists

* Which states are structurally alike?
    What we built: Unsupervised segmentation of 30 states on 15 de-correlated indicators
    Headline result: 5 state baskets (k = 5), from "Mature industrial & services cores" to
      "Remote frontier economies"

* How much should we trust the ranking?
    What we built: ±20% weight perturbation, equal-weight and PCA-weight challengers,
      counter-explanations
    Headline result: Leaders are robust for IT services (Karnataka, 100% of draws) and
      hospitality (Maharashtra, 100%); manufacturing and retail are near-ties (e.g.
      manufacturing 64.5 / 64.4 / 64.4) and the app says so

Governing principle. The index is a relative screening score. It is not a probability of commercial
success, profit or survival. Every number shown to a user traces to a raw government file with a
recorded SHA-256 checksum. Nothing is imputed.

Two architecture decisions shape everything below:

1. Honest scope over impressive scope. Five of six industries have no state-level sector output
   series, so we refused to train "five forecasts" on the same broad services aggregate (a
   common analytics anti-pattern). They are ranking-only by design.
2. Governance as a feature. Each value carries its source table, period and checksum on screen.
   In a decision product, auditability builds executive trust, and with it adoption.
3. Every reason must be a business reason. Each industry scores only indicators with a stated
   link to that business, and every strength or watch-out shown to a user says why it matters
   for that industry and how the state compares with the other states the user chose.

Managerial lens. The binding constraint was traceability, not data volume. A recommendation an
investment committee cannot audit is a liability. This is why every value is stored with its
provenance in data/source_register.csv, which holds 90 registered raw files, each with URL, SHA-256,
acquisition date and status.

1.2 Recency & time lag
----------------------

State macro data in India has a structural reporting lag of 12–24 months, and series are revised
between editions.

* State GSVA/GSDP (constant prices)
    Latest period used: FY 2024-25
    Approx. publication lag: ~9 months after FY end
    Implication: Freshest structural signal

* Gujarat state accounts
    Latest period used: FY 2022-23
    Approx. publication lag: not yet in the handbook
    Implication: Gujarat is ranked, but receives no forecast; disclosed on screen

* ASI (factories, workers)
    Latest period used: FY 2023-24
    Approx. publication lag: ~18 months
    Implication: Ecosystem/labour features lag one year

* PLFS unemployment (state)
    Latest period used: Jul 2023 – Jun 2024
    Approx. publication lag: ~4 months, but state annual only
    Implication: Labour pool measured, not district

* HCES consumption
    Latest period used: Aug 2023 – Jul 2024
    Approx. publication lag: ~6 months
    Implication: Snapshot; never interpolated

* TRAI internet
    Latest period used: Jun 2026
    Approx. publication lag: ~4 months
    Implication: Freshest digital signal

* Road length (state)
    Latest period used: 2020
    Approx. publication lag: ~3 years
    Implication: Replaced by national highways (2024) in scoring

How temporal discrepancies were reconciled

1. Latest observation per indicator, with its period displayed. Each value is shown with its own
   period, never relabelled as "current".
2. Explicit as-of joins for ratios. For example, highway km at end-March Y is divided by
   population for FY (Y-1)–Y. Where a state's population is not yet published (Gujarat), the
   latest earlier FY is used, and the note on that value says so.
3. Release-date control for the model (no look-ahead bias). Every observation carries an
   estimated first-publication date first_pub_est. A feature enters a forecast only if it had
   been published by the forecast date, and the build asserts this (max_feature_pub <=
   forecast_date).
4. Single price base. The new 2022-23 base GDP series (Feb 2026) had incomplete state
   back-series. Mixing it with the 2011-12 base would corrupt growth rates, so it is quarantined
   and the 2011-12 base is used.
5. Revision tracking. Against the 2023 edition, 19 of 82 pilot manufacturing cells were revised
   (e.g. Telangana 2022-23 -20.1%, UP 2022-23 -12.9%). Each was logged as an edition revision
   after confirming the parsed value is printed in the raw file. Limitation disclosed: the model
   backtest uses revised data, not real-time first estimates.

Managerial lens. Lag is unavoidable at state level, so the product treats freshness as a visible
attribute rather than hiding it. Each state gets a data-confidence label (High/Medium/Low) based on
observed-weight coverage and the number of pre-2023 indicators. Gujarat is labelled Medium: the
system flags it, so the executive doesn't have to discover it.

1.3 Data quality, auditability & imputation
-------------------------------------------

Imputation policy: none. A missing indicator is dropped and its weight is redistributed within its
dimension. A state missing a mandatory dimension is excluded with a stated reason. This is a
deliberate governance stance: imputing a favourable value would let missing data improve a state's
rank.

* Immutable raw layer
    Implementation: data/raw/<source>/<vintage>/, SHA-256 in register, re-hash check on every
      read
    Result on this build: 0 mismatches

* Duplicate detection
    Implementation: Hard failure on duplicate (state, period, indicator)
    Result on this build: 0 duplicates

* Price-base check
    Implementation: Pipeline quarantines any non-2011-12 cell
    Result on this build: 0 quarantined

* Outliers
    Implementation: YoY growth beyond ±40% flagged, not dropped
    Result on this build: 35 flags (pilots: UP manufacturing 2016-17 +47%; Telangana agriculture
      2019-20 +55%)

* Geography breaks
    Implementation: Fixed alias map; J&K excludes Ladakh from 2019-20, so that growth year is
      never a target
    Result on this build: Handled explicitly

* Fixture comparison
    Implementation: Parsed values vs 2023-edition reference
    Result on this build: 0 parsing bugs; 19 edition revisions

* Multi-source reconciliation
    Implementation: Hand-transcribed research extracts checked against parsed raw files
    Result on this build: 2 transcription errors found in the extracts (TN GSVA 2018-19; RJ
      services 2018-19); raw file is source of record

* Secondary values
    Implementation: Admitted only if the number is found next to the state name in a saved copy
      of the cited page
    Result on this build: 31 admitted (display only), 78 rejected with reasons

* End-to-end audit
    Implementation: 20 random numbers shown in the app re-read independently from raw files
    Result on this build: 20 / 20 pass

* Survey precision
    Implementation: HCES relative standard errors carried with each value
    Result on this build: e.g. Telangana urban MPCE RSE 16.9%, disclosed

Managerial lens. These controls are cheap relative to the cost of one wrong recommendation, and they
make the system defensible under due-diligence questioning. The audit trail
(reports/audit_report.md) is a deliverable in its own right.

2.1 Feature families (business constructs -> measurable proxies)
----------------------------------------------------------------

* Market demand
    Indicators (examples): Real GSDP (log), per-capita NSDP, urban/rural MPCE, personal loans
      per person, exports, tourist visits
    Proxy caveat stated in the app: High state demand is not store-site demand

* Infrastructure
    Indicators (examples): Energy shortage %, peak demand not met, power per person, national
      highways & rail per lakh people, internet subscriptions per 100
    Proxy caveat stated in the app: Subscriptions is not measured speed; shortage is not plant
      outages

* Economic outlook
    Indicators (examples): 3-year real growth momentum (sector or aggregate); validated
      manufacturing forecast
    Proxy caveat stated in the app: Services aggregate is broad, not sector-specific

* Labour availability
    Indicators (examples): Urban/rural unemployment rate (as available pool), factory workers,
      public specialists and PHC doctors per lakh
    Proxy caveat stated in the app: Pool size is not job-specific talent

* Healthcare care gap
    Indicators (examples): Public hospital beds per lakh, read as unmet demand (fewer public
      beds -> more patients relying on private care)
    Proxy caveat stated in the app: Not a measure of private capacity

* Business ecosystem
    Indicators (examples): Factories, manufacturing/services/financial share of GSVA, credit to
      industry, bank offices
    Proxy caveat stated in the app: Density can mean cluster or saturation

* Operating cost
    Indicators (examples): Rural wages, CPI, urban housing inflation, power T&D losses
    Proxy caveat stated in the app: Wage levels are rural series; no city office-rent series
      exists

* Policy & ease of doing business (v3)
    Indicators (examples): BRAP 2024 category and Top-Achiever reform areas; LEADS 2025 tier;
      Export Preparedness Index 2024; Startup Ranking 5.0
    Proxy caveat stated in the app: Official assessments of reform implementation and user
      feedback, not incentives on offer; categories are ordinal

* Educated labour (v3, inside Labour)
    Indicators (examples): Graduates among adults, adults with secondary+ education,
      diploma/certificate holders (PLFS); higher-education GER and new graduates a year per lakh
      people (AISHE)
    Proxy caveat stated in the app: Graduate counts are by state of institution, not residence;
      GER uses a 2011-census population base

Industry relevance rule (scoring v2). An indicator enters an industry's profile only with a written
business rationale (why in scoring/weights_v2.yaml), and the build tests enforce it. Version 1 used
a generic list, so a healthcare user was shown internet subscriptions as a strength and urban
unemployment as a watch-out. v2 removed those, added PHC doctors and population for healthcare, and
dropped household spending from IT services. It also dropped the ecosystem dimension for healthcare
and hospitality, because no auditable cluster indicator exists for them. Indicators that only matter
for some business models are brought in by operational needs: digital-first adds internet
subscriptions, power-intensive adds power indicators and logistics-heavy adds highways and rail. The
app tags each such reason with the need behind it.

Scoring v3: policy and educated labour. v3 adds a separate Policy & ease of doing business
dimension, scored from official government assessments, so the policy priority now changes the
ranking (in v2 it could not, for want of data). It also adds educated-labour supply to the labour
dimension. Ordinal categories (e.g. BRAP Fast Mover vs Aspirer) are scored as ordinal codes against
the same 30-state reference, so tied states share a percentile. They are shown by name, never as
numbers. Each industry uses the policy and education measures that matter to it:

* Manufacturing
    Policy indicators: BRAP category, BRAP Top-Achiever areas, Export Preparedness Index, LEADS
      tier
    Educated-labour indicators: Diploma/certificate share (technicians), secondary+ share (shop
      floor)

* Retail
    Policy indicators: BRAP category, BRAP Top-Achiever areas
    Educated-labour indicators: Secondary+ share (store staff)

* IT / professional
    Policy indicators: Startup Ranking (x2), BRAP category, BRAP Top-Achiever areas
    Educated-labour indicators: Graduate share (x2), new graduates per lakh (x2),
      higher-education GER

* Logistics
    Policy indicators: LEADS tier (x2), BRAP category, BRAP Top-Achiever areas, Export
      Preparedness Index
    Educated-labour indicators: via skilled-labour need only

* Healthcare
    Policy indicators: BRAP category, BRAP Top-Achiever areas
    Educated-labour indicators: Diploma/certificate share (nursing, paramedical)

* Hospitality
    Policy indicators: BRAP category, BRAP Top-Achiever areas
    Educated-labour indicators: Secondary+ share (front office)

The skilled-labour need adds the graduate share to any industry that lacks it and up-weights all
education measures. Every new value traces to a registered raw file. The audit script re-reads
numbers from the PDFs and checks each ordinal category by confirming the state is listed under it in
the official release; deliberately wrong categories fail. PDF parsing is verified by the tables' own
totals: PLFS shares add to 100, and AISHE male + female = total.

* Manufacturing
    Indicators scored (v2 base; v3 additions above): GSDP, per-capita income, exports · energy
      shortage, peak unmet, power per person, highways, rail · forecast + manufacturing momentum
      · factory workers, urban & rural labour pool · factories, manufacturing share, credit to
      industry · rural non-farm wage, T&D losses, CPI

* Retail
    Indicators scored (v2 base; v3 additions above): Urban MPCE, per-capita income, personal
      loans, GSDP · internet, energy shortage, highways · services momentum · urban labour pool
      · services share, bank offices · urban rent inflation, CPI

* IT / professional
    Indicators scored (v2 base; v3 additions above): GSDP, per-capita income · urban & total
      internet, energy shortage · services and financial-services momentum · urban labour pool ·
      services and financial-services share · urban rent inflation

* Logistics
    Indicators scored (v2 base; v3 additions above): GSDP, exports · highways, rail, energy
      shortage · whole-economy momentum · urban & rural labour pool · factories, credit to
      industry · rural non-farm wage, CPI

* Healthcare
    Indicators scored (v2 base; v3 additions above): Per-capita income, urban & rural MPCE,
      population, public-bed care gap · energy shortage, power per person · services momentum ·
      public specialists & PHC doctors per lakh · urban rent inflation, CPI

* Hospitality
    Indicators scored (v2 base; v3 additions above): Domestic & foreign tourist visits, urban
      MPCE · highways, rail · services momentum · urban labour pool · urban rent inflation, CPI

Derived features (computed, never imputed). Population is derived as NSDP ÷ per-capita NSDP, which
is the definition of per-capita NSDP. Every ratio carries all its component files. Power shortage %
is (requirement - availability) / requirement, floored at 0.

2.2 Transformation & normalisation
----------------------------------

The pilots differ by orders of magnitude in scale (UP: ~239 m people; Telangana: ~38 m), and the
national reference includes states with ~0.7 m people. The normalisation choice therefore drives the
result.

* Percentile rank vs a frozen national reference (mid-rank)
    Considered for: Scoring (production)
    Decision & reasoning: Chosen. Bounded 0–100, robust to outliers, and directly explainable
      ("better than 75% of states"). Freezing the 30-state reference means a state's score does
      not change when a user narrows the comparison set, a property tested in CI

* Min–Max
    Considered for: Scoring
    Decision & reasoning: Rejected: one extreme state (e.g. Arunachal's 278 km of highway per
      lakh people) compresses everyone else

* Z-score
    Considered for: Scoring
    Decision & reasoning: Rejected for scoring (unbounded, assumes symmetry); used for VIF and
      PCA where centring/variance matter

* Robust scaling (median/IQR)
    Considered for: Segmentation, first specification
    Decision & reasoning: Tested and rejected: produced singleton clusters (Mizoram, Arunachal)
      and failed the pre-stated cluster-size rule (§3.3)

* log/log1p
    Considered for: Skewed size counts (GSDP, exports, factories, workers, loans)
    Decision & reasoning: Applied before ranking/scaling so size differences don't swamp ratios

* Per-capita / per-lakh ratios
    Considered for: Absolute stocks (highways, beds, loans, bank offices)
    Decision & reasoning: Converts "big state" into "well-served state"

* Direction reversal
    Considered for: Cost/risk indicators
    Decision & reasoning: Score = 100 - percentile, so higher always means more attractive

Normalised indicator (production):

    p(s,j) = 100 x [ (number of reference values below x(s,j))
                     + 0.5 x (number of reference values equal to x(s,j)) ] / (size of R_j)

    p'(s,j) = p(s,j)          for a benefit indicator
    p'(s,j) = 100 - p(s,j)    for a cost / risk indicator

where R_j is the frozen national reference sample for indicator j (latest value for 28 states +
Delhi + J&K, transformed identically).

2.3 Excluded / dropped features
-------------------------------

Feature selection ran on the 30-state panel with both statistical and domain screens. Full log:
reports/segmentation/feature_screen.csv, VIF rounds in vif_rounds.csv.

Statistical screen (segmentation feature set)

* Urban MPCE
    Statistic: coverage 18/30
    Decision: Dropped (segmentation)
    Business logic: No imputation; kept in industry scoring where pilots are covered

* Rural non-farm wage
    Statistic: coverage 19/30
    Decision: Dropped (segmentation)
    Business logic: Same; Telangana is genuinely unpublished

* CPI inflation, rail route per lakh
    Statistic: coverage 29/30
    Decision: Dropped (segmentation)
    Business logic: One missing state would force imputation

* Peak demand not met
    Statistic: 100% of states share one value (0)
    Decision: Dropped: zero variance
    Business logic: India's peak deficit is now negligible, so it cannot discriminate

* Real GSDP (log)
    Statistic: VIF 505
    Decision: Dropped
    Business logic: Size is already carried by exports and credit depth

* Per-capita NSDP
    Statistic: VIF 124
    Decision: Dropped
    Business logic: Collinear with loans per capita and power per capita (affluence)

* Factory workers (log)
    Statistic: VIF 76
    Decision: Dropped
    Business logic: Duplicates factory count and exports

* Bank offices per lakh
    Statistic: VIF 73
    Decision: Dropped
    Business logic: Collinear with credit depth

* Internet subs per 100
    Statistic: VIF 17.6
    Decision: Dropped
    Business logic: Tracks affluence and urbanisation

* Manufacturing share
    Statistic: VIF 13.4
    Decision: Dropped
    Business logic: Captured by credit-to-industry share

* Factories (log)
    Statistic: VIF 10.7
    Decision: Dropped
    Business logic: Last to exceed threshold

* 15 retained features
    Statistic: all VIF <= 5.4
    Decision: Kept
    Business logic: Services/financial share, growth momentum, power, shortage, highways, credit
      share, CD ratio, loans, urban & rural UR, T&D losses, exports, beds

The rule was iterative: remove the highest-VIF feature, recompute, and stop when the maximum VIF is
10 or below.

Domain-driven exclusions (all models)

* Commercial rents, plot prices, industrial tariffs, outage hours
    Why: No comparable public state series; never estimated

* Policy incentives on offer (subsidies, tax holidays)
    Why: Not comparable across states and not published as a state series; only
      reform-implementation assessments are scored

* Company registrations (MCA)
    Why: Not obtainable without bypassing a CAPTCHA; registered office is not operating site

* District youth unemployment
    Why: No official series exists; the app says so instead of estimating

* Six separate "sector forecasts" from the services aggregate
    Why: Would mislabel one broad target as six independent forecasts (rule 8 of the blueprint)

Managerial lens on VIF in the scoring engine. The production index does keep some correlated
indicators (e.g. GSDP and per-capita NSDP inside "Demand"). This is deliberate: within a dimension,
correlated indicators are weighted to a fixed dimension total, so redundancy cannot inflate a
pillar's influence. VIF matters most in segmentation, where every feature contributes to distance,
and that is where it was enforced.

3. MACHINE LEARNING MODELS & STATE SEGMENTATION
===============================================

The project uses two complementary model types. The supervised forecast answers "will this state's
sector grow?" The unsupervised segmentation answers "which states are structurally alike?" A third
component, the suitability index, answers "which state best fits this business?" and is covered in
§4.

3.1 Supervised: one-year-ahead manufacturing growth forecast
------------------------------------------------------------

Target

    g(s,t+1) = 100 x ( Y(s,t+1) / Y(s,t) - 1 )
    where Y = real manufacturing GSVA (RBI Table 34, 2011-12 prices)

Design. The panel is national: 30 states, 351 labelled state-years, origins FY 2012-13 to 2023-24.
Features are lag-only: last-year and 2-year growth, 3-year mean, volatility, whole-economy growth,
log per-capita income, manufacturing share and national mean growth. Business and infrastructure
lags (ASI, credit, power) were tested in ablations.

* Persistence (last year's growth)
    Why considered: Must-beat baseline
    Validation MAE (pp, non-COVID): 13.37

* 3-year mean
    Why considered: Stable baseline
    Validation MAE (pp, non-COVID): 10.87

* Ridge (α = 100), macro lags
    Why considered: Regularised, interpretable, suited to small panels
    Validation MAE (pp, non-COVID): 9.56 (selected)

* ElasticNet (α = 0.5)
    Why considered: Sparse alternative
    Validation MAE (pp, non-COVID): 9.73

* Random Forest (depth 3, leaf 10)
    Why considered: Non-linearity check
    Validation MAE (pp, non-COVID): 9.92

* Gradient boosting (depth 2)
    Why considered: Flexible check
    Validation MAE (pp, non-COVID): 10.43

Protocol. The CV is an expanding window by year and is never shuffled. Validation target years run
2017-18 to 2023-24, with COVID years reported separately. FY 2024-25 is an untouched hold-out,
scored once. Scalers and imputers sit inside sklearn Pipelines, so they are fitted on training folds
only.

Acceptance rule (fixed before results). The model must be >=5% better than the best baseline, win in
>=60% of non-COVID years, and be no worse on the hold-out.

* MAE improvement vs 3-year mean
    Result: +12.1%
    Pass: Pass

* Non-COVID validation years won
    Result: 4 / 5
    Pass: Pass

* Hold-out FY 2024-25 MAE
    Result: 3.31 vs 3.88 pp
    Pass: Pass

* Year-block bootstrap of the gain
    Result: -1.31 pp (90% CI -2.89 to +0.20)
    Pass: Caution interval crosses zero, disclosed

Managerial lens. Deep learning, LSTMs and XGBoost were deliberately not used: with ~13 years per
state, complexity would overfit, and the ablations confirm that added features did not help. The
forecast is shown with its 80% band (approx. ±12 pp) and its error history, so a strategist reads it
as a direction, not a promise.

3.2 Unsupervised: algorithm selection
-------------------------------------

* K-Means (100 initialisations)
    Fit for 30 macro-units: Fast, centroid profiles map naturally to business personas
    Decision: Primary

* Ward hierarchical
    Fit for 30 macro-units: Deterministic, gives a dendrogram for explaining nesting; Ward
      minimises within-cluster variance like K-Means
    Decision: Cross-validation of K-Means (agreement ARI 0.76 at k = 5)

* DBSCAN
    Fit for 30 macro-units: Density-based; flags outliers
    Decision: Tested and rejected: across an ε grid it found 1–2 clusters with 0–10 states
      labelled noise. With 30 points in 15 dimensions density is too thin, and calling a state
      "noise" is not actionable

* Gaussian mixtures / spectral
    Fit for 30 macro-units: Need more data for stable covariances
    Decision: Not justified at n = 30

3.3 Evaluation & hyperparameter decisions (choosing k)
------------------------------------------------------

Pre-stated selection rule: k must be in 3–6 (k = 2 is not a segmentation; above 6 is unusable for 30
states), every cluster must hold at least 3 states, and bootstrap stability must be ARI >= 0.6.
Among the qualifying k, the highest silhouette wins.

Primary specification: percentile-rank features

-  -------  --------------------  --------------  ---------------------  ------------  -------------  ----------------
2  28.7     0.180                 1.75            0.19                   12            0.49           Fail (k range)
3  22.9     0.192                 1.50            0.81                   9             0.73           Pass
4  20.2     0.201                 1.41            0.76                   3             0.68           Pass
5  17.8     0.213                 1.31            0.76                   3             0.66           Pass (chosen)
6  16.2     0.175                 1.37            0.65                   3             0.54           Fail (stability)

Figures: reports/segmentation/k_selection.png (elbow, silhouette, Davies-Bouldin), dendrogram.png,
pca_clusters.png.

Statistical optimality vs business interpretability

- The elbow is shallow, with no sharp knee. Silhouette peaks at k = 5 and Davies-Bouldin is
  lowest at k = 5, so the statistics and the rule agree.
- k = 3 is the "stable" alternative (bootstrap ARI 0.73) but merges three very different
  small-state groups into one basket. Business value comes from separating hill industrial
  enclaves from remote frontier economies, because their expansion logic differs completely.
- Transparency note. The first specification (robust scaling) produced a degenerate 28 / 1 / 1
  split and failed the rule. We switched to percentile-rank scaling after seeing that result. It
  is the same normalisation the suitability index uses, and the rejected run is saved
  (k_selection_robust_rejected.csv). Rank vs z-score K-Means agreement is ARI 0.84, so the
  solution is not an artefact of scaling.
- Honest limitation. A silhouette of 0.21 means the structure is real but weak: Indian states
  lie on a continuum. The baskets are a descriptive lens for portfolio thinking and are not used
  to score states.

4. MULTI-CRITERIA WEIGHTING & SCORING FRAMEWORK
===============================================

4.1 Weighting methodology
-------------------------

Production weights are heuristic design defaults, not learned optima. This is a deliberate MCDA
(multi-criteria decision analysis) choice. They come from the project blueprint's expert-style
pillar split (demand 25, infrastructure 20, outlook 20, labour 15, ecosystem 10, cost/policy 10),
tilted per industry using documented domain rationale. For example, manufacturing upweights
infrastructure and ecosystem, and hospitality upweights tourist demand.

Industry           Demand  Infra.  Outlook  Labour  Ecosystem  Cost  Policy
-----------------  ------  ------  -------  ------  ---------  ----  ------
Manufacturing      15      25      15       15      10         10    10
Retail             30      15      15       15      10         10    5
IT / professional  15      20      15       25      10         5     10
Logistics          20      25      15       10      10         10    10
Healthcare         35      15      10       25      —          10    5
Hospitality        40      20      10       15      —          10    5

— = no ecosystem dimension (no auditable indicator); its weight is spread over the other dimensions.

Why not purely statistical (PCA/factor) weights in production? PCA weights variance, not business
relevance. An indicator that varies a lot can be strategically minor. AHP pairwise elicitation was
not run because no expert panel was convened; that is listed as the next step. Instead we treat PCA
and equal weights as challenger models to stress-test the design weights:

priorities should matter. Logistics diverges most under PCA weights because PCA puts far more weight
on ecosystem than the design's 10%. A manager who believes clustering effects dominate logistics
should raise that weight, and the what-if panel lets them.

4.2 Composite index formulation
-------------------------------

1. Indicator score: p'(s,j) as defined in §2.2.

2. Dimension score. Only observed indicators count, and indicator weights renormalise over what
   is observed:

    D(s,d) = sum over observed indicators j in dimension d of
             [ v_j / (sum of v_k over the observed indicators in d) ] x p'(s,j)

Here J_d is the set of indicators in dimension d, O_s the set of indicators observed for state s,
and v_j the within-dimension indicator weight.

3. User-adjusted dimension weights. Each of up to three chosen priorities applies a multiplier
   of 1.6; each supported operational need applies a multiplier of 1.15 or 1.25:

    w'_d = w_d x (1.6 for each priority mapped to d) x (need multiplier for each need mapped to d)
    normalised weight:  w^_d = w'_d / (sum of w' over all dimensions)

4. Composite suitability index. Missing dimensions are dropped and the remaining weights
   renormalised:

    S_s = [ sum over observed dimensions d of w^_d x D(s,d) ] / [ sum of w^_d over those dimensions ]
    S_s lies between 0 and 100

5. Eligibility gate. A state is excluded (not scored low) if any mandatory dimension for the
   industry is empty. With fewer than 2 eligible states, no ranking is produced.

6. Forecast factor. The forecast enters "Outlook" only if the industry's model passed validation
   and the state has current data. Otherwise outlook uses historical momentum, labelled as such.

7. Explanations (strengths and watch-outs). Reasons are relative to the other states the user is
   comparing, not to the national median, so they explain the rank the user actually sees:

    gap(s,j)   = p'(s,j) - median of p'(e,j) over the other compared states e
    lever(s,j) = gap(s,j) x (effective indicator weight) x (normalised dimension weight w^_d)

Here E is the set of eligible compared states. The largest positive levers are shown as strengths
and the largest negative ones as watch-outs. An item is shown only if the absolute gap is at least 5
percentile points and the raw difference from the peers' median is material: at least the
indicator's floor (for example 0.1 pp for energy shortage, 0.5 pp for growth rates) or 5% of the
median. This stops a 0.03% vs 0.00% shortage from being presented as a business reason. Because the
lever uses the user's effective weights, priorities and needs change which reasons appear, and each
reason carries tags such as "your priority: infrastructure" or "your need: digital-first". The
browser and Python engines produce identical reasons (parity test).

4.3 Sensitivity & robustness
----------------------------

Method. For each of 500 draws, every dimension weight is multiplied by a random factor between 0.8
and 1.2 and renormalised, and the pilots are re-ranked. In the app each state shows the share of
draws in which it keeps its rank, plus its best and worst rank.

Industry (default weights)  Leader       Gap 1st–2nd (pts)  Leader kept in draws  Mean ρ vs base  Worst ρ
--------------------------  -----------  -----------------  --------------------  --------------  -------
IT / professional           Karnataka    3.9                100%                  0.98            0.86
Hospitality                 Maharashtra  1.0                100%                  0.95            0.86
Healthcare                  Tamil Nadu   0.2                74%                   0.99            0.96
Logistics                   Maharashtra  0.4                71%                   0.95            0.82
Retail                      Karnataka    0.04               51%                   0.98            0.93
Manufacturing               Telangana    0.04               39%                   0.93            0.82

Counter-explanation. For every result the engine computes what would make the runner-up win. Example
(UP manufacturer demo, power/logistics/labour priorities): "Gujarat scores 95 vs 63 for Telangana on
business ecosystem (mainly manufacturing share of GSVA). If that dimension carried about 1.7x its
current weight, Gujarat would rank first."

Policy & strategic allocation implications

- Robust leaders (IT services -> Karnataka, hospitality -> Maharashtra) can support a
  concentrated bet.
- Near-ties (manufacturing default: Telangana 64.5, Tamil Nadu 64.4, Maharashtra 64.4; retail:
  Karnataka 71.4, Telangana 71.3; healthcare: Tamil Nadu 67.5, Karnataka 67.3) argue for a
  shortlist and site visits, not a single-state commitment. The app states this explicitly.
- Personalisation helps: once the UP manufacturer's priorities are applied, Telangana's lead
  becomes stable (same rank in 100% of draws). The engine converts stated strategy into a
  clearer answer.
- For policymakers, weight-insensitive weakness (e.g. UP's infrastructure dimension at 30/100
  under every reasonable weighting) is a robust intervention target, unlike rank changes driven
  by weighting choices.

5.3 Managerial takeaways & strategic actionability
--------------------------------------------------

How a corporate strategist uses it

* Portfolio framing
    Use of the system: Start from the basket, not the state
    Example from this build: A cost-led plant looks first at Emerging Growth Markets (UP, RJ); a
      skilled-services centre at Mature Cores

* Shortlisting
    Use of the system: Top-3 index with priorities applied
    Example from this build: UP manufacturer (power, logistics, labour) -> Telangana 65.3,
      Gujarat 63.7, Tamil Nadu 63.3

* Stress-testing
    Use of the system: Stability panel + counter-explanation
    Example from this build: Telangana keeps rank 1 in 100% of draws; Gujarat wins only if
      ecosystem weight rises ~1.7x

* Due diligence
    Use of the system: Watch-outs + data confidence
    Example from this build: Telangana: no rural wage series (cost uses other indicators);
      Gujarat: accounts end FY 2022-23, Medium confidence

* Capital allocation
    Use of the system: Concentrate where robust, stage where near-tied
    Example from this build: Manufacturing default is a three-way near-tie: phase capex behind
      site-level diligence in all three

How a policymaker uses it

- Diagnose robust gaps. Dimension scores that stay low under every weighting (e.g. UP and RJ
  infrastructure) are investment-attraction bottlenecks.
- Benchmark within baskets. Compare a state with its structural peers, not with the national
  leader. That gives fairer targets for, say, Rajasthan versus Madhya Pradesh or Odisha.
- Prioritise data infrastructure. The data gaps the system discloses (state youth unemployment,
  Gujarat's lagged accounts, rural wages) are themselves policy findings: missing data raises
  investors' perceived risk.

What the business gets (ROI)

- Time. First-pass state screening drops from weeks of analyst desk research to minutes, with a
  full evidence pack.
- Risk. Visible caveats, confidence labels and near-tie warnings reduce the chance of
  over-committing on a fragile ranking.
- Defensibility. Every figure is audit-traceable (20/20 random checks pass) and weights are
  versioned. The recommendation can be challenged and reproduced.

Limitations the panel should weigh

1. State averages hide corridor and district variation; this is screening, not site selection.
2. One data vintage: the forecast backtest uses revised data.
3. Weights and the indicator-to-industry mapping are expert-style defaults (v3), not
   AHP-elicited or learned.
6. Policy categories are ordinal and coarse (BRAP 2024 placed no state above Fast Mover), so
   they separate states less finely than numeric indicators.
4. Segmentation structure is weak (silhouette 0.21): useful for framing, not for hard rules.
5. Ookla speed data is non-commercial (CC BY-NC-SA). A commercial deployment needs a licence.

Recommended next steps

1. AHP weight elicitation with 5–7 industry experts, and a consistency ratio below 0.1.
2. Add Gujarat DES figures for FY 2023-25 as a separately labelled panel.
3. District layer (Ookla speeds already extracted for 28 cities) for second-stage site
   screening.
4. Real-time-vintage archive of RBI editions for a true out-of-sample forecast test.
5. A REST API around the pure scoring function for CRM/ERP integration.
